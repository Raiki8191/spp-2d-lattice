# Shortest-Path Percolation 二次元正方格子シミュレーション設計

## 1. 研究モデル

本研究では、開放境界を持つ `L x L` の二次元正方格子上で Shortest-Path Percolation（SPP）をシミュレーションする。格子は無向・無重みとし、頂点数と初期辺数はそれぞれ次のとおりである。

- 頂点数: `N = L^2`
- 初期辺数: `M0 = 2L(L - 1)`

各ステップで、異なる2頂点 `source` と `target` を全頂点から一様ランダムに選ぶ。現在有効な辺だけを用いて最短距離 `Q` を求め、`Q <= C` の場合は選択した最短経路上の全辺を削除する。`Q > C` の場合、または距離 `C` 以内に `target` へ到達できない場合は、辺状態を変更しない。

各 run の開始時には完全な正方格子を再生成または初期状態へ戻す。同一 run 内では辺削除を累積し、削除済みの辺が再び有効になることはない。

### 有限予算と無限予算相当

異なる2頂点間の単純な最短経路長は最大でも `N - 1` である。このため `C >= N - 1`、特に設定上わかりやすい `C = N` は、同一連結成分内にある頂点対の要求を常に受理する「無限予算相当」とみなせる。頂点対が異なる連結成分に属する場合は、無限予算相当でも到達不能として棄却する。本研究では有限 `C` の結果と無限予算相当の結果を比較対象とする。

### 複数の最短経路の扱い

#### 原論文の記述

原論文には、`source` と `target` の間に複数の最短経路が存在する場合、その中から1本をランダムに選択すると記載されている。ただし、全最短経路に対して厳密に一様な確率で選ぶことまでは断定しない。

#### 本研究の具体的規則

本研究では、隣接頂点の格納順、頂点ID、格子方向によるバイアスを避ける具体的規則として、全最短経路から1本を一様ランダムに選択する。

#### 初期実装で採用する方法

初期実装から、BFSと最短経路DAGを用いる厳密な一様選択を採用する。

1. 有効辺だけを探索し、深さ `C` までのBFSで各頂点の最短距離を求める。
2. `target` の最短距離を `Q` とし、`Q <= C` の場合、`distance[v] = distance[u] + 1` を満たす有効辺だけから最短経路DAGを定義する。
3. `source` から各頂点までの最短経路数を、BFSの距離順に動的計画法で数える。経路数はオーバーフローを避けるため `BigInteger` で保持する。
4. `target` から `source` へ後ろ向きに辿る。現在の頂点 `v` の前駆候補 `u` のうち、`distance[u] = distance[v] - 1` を満たす頂点を列挙し、`source` から `u` までの経路数に比例する確率で1頂点を選ぶ。
5. 選ばれた前駆辺を経路へ追加し、`source` に到達するまで繰り返す。

この後ろ向き選択により、各最短経路は同じ確率で選択される。重み合計を上限とする `BigInteger` 乱数は、乱数値に剰余（mod）を取る方法では生成しない。上限のビット長に合わせて候補値を生成し、上限以上の候補を捨てて再抽選する棄却法により、`0` 以上、重み合計未満の整数を一様に生成する。BFSは `target` を最初に発見した時点では直ちに終了せず、全最短経路数を確定するため、少なくとも距離 `Q - 1` の全頂点から距離 `Q` への遷移を処理する。

#### 初期実装の限界

`BigInteger` を用いるため一様性と経路数の正確性は保てるが、最短経路数が非常に大きい場合は、固定幅整数を使う実装より計算時間とメモリ使用量が増える。また、要求ごとにBFSと経路数計算を行うため、大きな `L`、`C`、`maxSteps` では実行時間が支配的になる可能性がある。性能上の問題が確認された場合も、近似法への変更は一様性への影響を評価してから行う。

## 2. 1試行の処理フロー

1 run は次の順序で処理する。

1. `SquareLattice` を初期化し、全ての `activeEdge[edgeId]` を `true` にする。
2. `runSeed` から頂点対選択用と最短経路選択用のシードを決定的に生成し、用途別の乱数生成器を初期化する。
3. ステップ0の連結成分を測定し、初期状態をCSVへ記録する。
4. 異なる2頂点 `source`、`target` を一様ランダムに選択する。
5. 有効辺上で深さ `C` までBFSを行う。
6. `target` が距離 `Q <= C` で到達可能なら、最短経路DAGから最短経路を1本一様ランダムに選ぶ。
7. 選択した経路に含まれる全ての辺を無効化し、`accepted_requests` を1増やす。1本の経路内の各辺は探索時点で有効なため、削除辺数には各辺を1回だけ加える。
8. `target` が距離 `C` 以内で到達不能なら、辺状態を変えず `rejected_requests` を1増やす。
9. 処理済みの全要求数 `t` を `step` として1増やし、選択した測定方針の条件を満たした時点で連結成分を再計算してCSVへ記録する。
10. `remainingEdges == 0` または `step == maxSteps` になるまで手順4から9を繰り返す。
11. 終了時点が未測定なら最終状態を追加測定する。同じ `step` の行は重複して出力しない。
12. 全辺削除による正常終了と `maxSteps` による打ち切りを区別し、run要約へ終了理由を記録する。

ここで `Q > C` は、深さ `C` までの制限付きBFSでは「距離 `C` 以内に到達できない」場合と同じ rejected として扱う。正確な `Q` が `C` よりどれだけ大きいかは求めない。

## 3. データ構造

### 頂点

格子座標を0始まりの `(row, column)` とし、頂点IDを次で定義する。

```text
vertexId = row * L + column
row      = vertexId / L
column   = vertexId % L
```

有効な頂点IDの範囲は `0 <= vertexId < L^2` である。

### 辺と隣接情報

各無向辺に `0` から `M0 - 1` までの一意な `edgeId` を割り当てる。同じ無向辺を両端の頂点から参照しても、同じ `edgeId` を使用する。

隣接情報には、各頂点について次の組を保持する。

- 隣接頂点ID
- 対応する無向辺の `edgeId`

正方格子の次数は最大4であるため、固定長に近いコンパクトな隣接配列、または頂点ごとの配列として表現できる。隣接順は結果の正しさに影響させない。初期版の開放境界では、角の次数は2、角以外の境界頂点は3、内部頂点は4となる。

辺状態は次の配列で管理する。

```java
boolean[] activeEdge;
```

`activeEdge[edgeId] == true` は有効、`false` は削除済みを表す。削除時に隣接配列を組み替えず、BFSや連結成分探索時に辺状態を確認する。

### 探索用ワーク領域

要求処理用BFSでは、少なくとも次を使用する。

- BFSキュー
- 各頂点の最短距離
- 各頂点までの最短経路数 `BigInteger`
- 最短経路の後ろ向き選択に使う前駆候補
- 選択された経路の `edgeId` 列

連結成分測定では、訪問済み配列、探索キューまたはスタック、各成分の頂点数を使用する。頻繁なメモリ確保を避けるため、run内で再利用可能なワーク配列とすることを検討する。

## 4. クラス責務

### `ShortestPathPercolation`

- アプリケーションのエントリーポイント
- `SPPConfig` の生成または読み込み
- run の反復実行
- `SPPSimulator`、`ClusterAnalyzer`、`CsvWriter` の連携
- 出力先の準備と実行概要の表示

### `SPPConfig`

以下の初期設定項目を保持する。

| 項目 | 意味 |
|---|---|
| `L` | 格子の一辺の頂点数 |
| `C` | 削除を受理する最短距離の上限 |
| `runs` | 独立run数 |
| `maxSteps` | 1 run当たりの最大要求数 |
| `measurementInterval` | 連結成分の測定間隔 |
| `measurementPolicy` | 測定契機。初期確認は `STEP_INTERVAL` |
| `boundaryCondition` | 境界条件。初期版は `OPEN` のみ |
| `baseSeed` | runシード生成の基準値 |
| `outputDirectory` | CSV出力先ディレクトリ |

`L >= 1`、`C >= 1`、`runs >= 1`、`maxSteps >= 0`、`measurementInterval >= 1` などを検証する。`L = 1` は格子構造の単体テストやステップ0の測定には許可する。一方、異なる2頂点を選ぶ通常実験、すなわち `maxSteps > 0` の設定では `N = L^2 >= 2` を要求する。初期版で `OPEN` 以外が指定された場合は、暗黙に置換せず設定エラーとする。

### `SquareLattice`

- `L x L` 開放境界格子の生成
- 頂点IDと座標の変換
- 無向辺への一意な `edgeId` の割り当て
- 隣接頂点と `edgeId` の参照提供
- `activeEdge` の初期化、参照、削除
- 初期辺数、削除辺数、残存辺数の提供

### `SPPSimulator`

- 1 run の状態とステップ進行の管理
- 異なる2頂点の一様ランダム抽選
- 深さ `C` までのBFS
- 最短経路数の計算と最短経路の一様ランダム選択
- 選択経路上の辺削除
- accepted／rejected件数の更新
- 全辺削除または `maxSteps` による停止と終了理由の管理

### `ClusterAnalyzer`

- 現在有効な辺だけを用いたBFSまたはDFS
- 全連結成分サイズの再計算
- 最大・第2最大連結成分サイズの算出
- 有限クラスターの平均サイズの算出

### `SPPResult`

- 1つの測定時点に対応する不変な結果データの保持
- run情報、設定値、辺数、連結成分統計、要求数、シードの保持
- CSV列の計算元となる値の型を明確化

### `CsvWriter`

- CSVヘッダーの出力
- `SPPResult` の列順に従った出力
- 文字コードをUTF-8に固定
- 出力ディレクトリの作成
- ファイルのライフサイクルとI/O例外の管理

## 5. 乱数シード規則

run番号は0始まりとし、各runのシードを次で定義する。

```text
runSeed = baseSeed + run
```

`runSeed` から、互いに異なる固定定数を用いた決定的な64ビットmix関数によって、次の2つのシードを生成する。

```text
pairSeed = mix64(runSeed XOR PAIR_STREAM_CONSTANT)
pathSeed = mix64(runSeed XOR PATH_STREAM_CONSTANT)
```

- `pairRandom`: 異なる2頂点の選択だけに使用する。
- `pathRandom`: 複数の最短経路から1本を選択する処理だけに使用する。

用途別の乱数生成器はrunの途中で作り直さない。最短経路選択アルゴリズムが消費する乱数の個数や実装方法を変更しても、頂点対系列が変化しないことを保証する。この規則により、同じ設定、同じ実装、同じ `baseSeed` なら結果を再現でき、将来runを並列化しても実行順序に依存しない。

`baseSeed + run` が `long` の範囲を超えないことを設定検証または安全な加算で確認する。mix関数、固定定数、Javaの乱数生成器の種類は実装および実験記録で固定する。CSVの `seed` 列にはrun識別の基準となる `runSeed` を記録し、再現性の詳細が必要な場合はrun要約に `pairSeed` と `pathSeed` も記録する。

## 6. CSV仕様

CSVは1行を「1 run における1測定時点」とする。列順は次で固定する。

| 列 | 型 | 定義 |
|---|---:|---|
| `run` | int | 0始まりのrun番号 |
| `L` | int | 格子の一辺の頂点数 |
| `C` | int | 最短距離の受理上限 |
| `step` | long | この時点までに処理した全要求数 `t` |
| `removed_edges` | long | 初期状態から削除された一意な無向辺数 |
| `remaining_edges` | long | `M0 - removed_edges` |
| `removed_edge_fraction` | double | 削除辺密度 `p = removed_edges / M0` |
| `largest_cluster_size` | int | 最大連結成分の頂点数 |
| `largest_cluster_fraction` | double | `largest_cluster_size / L^2` |
| `second_largest_cluster_size` | int | 第2最大連結成分の頂点数。成分が1個だけなら0 |
| `mean_cluster_size` | double | 最大連結成分を除く有限クラスターの重み付き平均サイズ |
| `accepted_requests` | long | `Q <= C` で経路削除が実行された累積受理イベント数 |
| `rejected_requests` | long | 距離 `C` 以内に到達できず変更しなかった累積要求数 |
| `seed` | long | そのrunで使用した `runSeed` |

全ての測定行で次の関係を満たす。

```text
accepted_requests + rejected_requests = step
removed_edges + remaining_edges = M0
0 <= removed_edge_fraction <= 1
0 <= largest_cluster_fraction <= 1
```

`mean_cluster_size` は、サイズ `s` の有限クラスター数を `n_s` として次で定義する。

```text
mean_cluster_size = sum(s^2 * n_s) / sum(s * n_s)
```

最大連結成分を1個だけ除外する。最大サイズが同率の成分が複数ある場合も、そのうち1個だけを最大連結成分として除外し、残りは有限クラスターに含める。分母が0の場合は `0.0` とする。

`M0 = 0` となる `L = 1` では `removed_edge_fraction` を `0.0` とする。

### 測定方針

時間軸と辺削除の進行を混同しないため、次を区別する。

- `step = t`: acceptedとrejectedを含む全要求数。
- `accepted_requests`: 経路削除が実行された受理イベント数。
- `p = removed_edges / M0`: 初期辺に対する削除済み辺の割合。

測定契機は次の方針から選ぶ。

- `STEP_INTERVAL`: `t` が `measurementInterval` の倍数になったときに測定する。動作確認と初期実装で使用する。
- `ACCEPTED_EVENT`: acceptedイベントの直後に測定する。状態が変化しないrejected要求では測定しない。本実験の候補とする。
- `REMOVED_FRACTION_GRID`: あらかじめ定めた `p` のグリッド値を初めて超えたacceptedイベントの直後に測定する。1回の経路削除で複数の未測定グリッドを越えた場合は、その時点の状態を1回記録して越えたグリッドを消化し、同一stepの重複行を作らない。本実験の候補とする。

全方針でステップ0と終了時点を測定し、同じ `step` の行は重複させない。`measurementInterval` は `STEP_INTERVAL` の間隔として使用する。出力順は原則として `run`、`step` の昇順とする。Python解析では、要求時間 `t` に対する変化と削除辺密度 `p` に対する変化の両方を対象とする。

将来のCSV列候補として `last_path_length` を追加できるようにする。accepted直後なら直近に削除した最短経路長 `Q`、rejectedまたはステップ0の測定なら欠損値とする。これにより1イベントで削除された辺数の変化を追跡できる。

### run要約と停止理由

runは `remaining_edges == 0` または `step == maxSteps` で終了する。全辺削除は正常完了、辺が残った状態での `maxSteps` 到達は打ち切りとして区別する。将来のrun要約には、例えば次のいずれかを記録する。

- `termination_reason`: `ALL_EDGES_REMOVED` または `MAX_STEPS`
- `completed`: 全辺削除まで到達したかを表すboolean

run要約には最終 `step`、`accepted_requests`、`removed_edges`、`remaining_edges`、`runSeed` も併記し、有限時間で打ち切られたrunを解析時に識別できるようにする。

## 7. 段階的実装計画

1. **プロジェクト基盤**: Gradle、標準ディレクトリ、テスト基盤、パッケージを用意する。
2. **設定**: `SPPConfig` と境界条件の表現、入力値検証を実装する。
3. **格子**: `SquareLattice` の頂点・辺生成、edgeId、隣接情報、`activeEdge` を実装する。
4. **要求処理**: 独立した頂点対用乱数による抽選、制限付きBFS、accepted／rejected判定を実装する。
5. **経路選択**: 独立した経路用乱数、`BigInteger` と棄却法による最短経路の厳密な一様ランダム選択を実装する。
6. **辺削除**: 選択経路のedgeIdを無効化し、累積辺数との整合性を保つ。
7. **測定**: `ClusterAnalyzer` で全連結成分と各統計量を計算する。
8. **結果出力**: `SPPResult` と `CsvWriter`、`STEP_INTERVAL` 測定、run終了理由を実装し、CSV仕様を固定する。
9. **複数run**: runごとの初期化、用途別乱数シード、停止条件、逐次実行を完成させる。並列化は再現性と出力順を保てることを確認した後に検討する。
10. **Python解析**: CSVの集約、誤差評価、臨界点推定、有限サイズスケーリング、図の生成を実装する。

### 有限サイズスケーリング方針

二次元格子では頂点数 `N` ではなく、線形サイズ `L` を有限サイズスケーリングの基本変数とする。削除辺密度 `p = removed_edges / M0` に対する疑似臨界点を `p_c(L)` とし、臨界点付近で次の関係を検証する。

```text
P_c(L) ~ L^(-beta/nu)
S_c(L) ~ L^(gamma/nu)
|p_c(L) - p_c| ~ L^(-1/nu)
```

ここで `P_c(L)` は `p_c(L)` における最大連結成分割合、`S_c(L)` は最大連結成分を除いた平均有限クラスターサイズを表す。`p_c(L)` の推定方法は、`S_c(L)` のピーク、サイズ間交差、将来導入するスパニング確率などを比較して決定し、採用方法を解析記録に残す。

ERネットワークや平均場モデルの臨界指数をそのまま仮定せず、二次元格子上のSPPデータから `beta/nu`、`gamma/nu`、`1/nu` および `p_c` を推定する。既知の指数を参照する場合も、比較対象として扱う。

将来の観測量候補として、上下方向または左右方向を結ぶ有効辺上の連結成分が存在するかというスパニング判定、およびrun間のスパニング確率を追加する。開放境界における方向別判定と「いずれかの方向」の判定を区別する。

## 8. テスト方針

### 単体テスト

- `L = 1, 2, 3` で頂点数が `L^2`、辺数が `2L(L - 1)` となること。
- `C = 0` を拒否し、`C >= 1` を受理すること。`L = 1` は構造テストでは許可し、`maxSteps > 0` の通常実験では拒否すること。
- 全edgeIdが一意で連続し、1本の無向辺を両端から同じedgeIdで参照できること。
- 開放境界で角、角以外の境界、内部の次数がそれぞれ2、3、4になること。ただし小さい `L` の退化ケースは個別の期待値を使うこと。
- BFSが既知の最短距離を返し、削除辺を通らず、深さ `C` を越えて探索しないこと。
- 複数最短経路を持つ小格子で、最短経路数が正しく計算されること。
- 後ろ向き選択が常に最短経路を返し、固定シードで再現可能なこと。
- `BigInteger` の一様乱数生成がmodを使わず棄却法で行われ、上限が2の累乗でない場合にも偏りがないこと。
- 多数回の統計テストで、対称な複数最短経路の選択頻度が一様分布と整合すること。統計テストには過度に厳しい閾値を設定しない。
- accepted時に選択経路上の辺だけが削除されること。
- rejected時に `activeEdge` と削除辺数が変化しないこと。
- 連結成分の最大、第2最大、平均サイズが手計算と一致すること。
- `L = 1`、全辺削除、成分1個だけ、最大成分同率などの境界条件を正しく扱うこと。
- `C >= N - 1` では、同一連結成分内の全ての頂点対が受理されること。

### 結合テスト

- 同一run内で辺削除が累積し、次の要求のBFSへ反映されること。
- runが変わると全辺が有効な状態へ戻ること。
- 同じ設定とシードでCSVが再現されること。
- 経路選択処理が消費する乱数回数を変えても、同じ `pairSeed` から生成される頂点対系列が変わらないこと。
- `accepted_requests + rejected_requests = step` など、CSVの不変条件を満たすこと。
- `STEP_INTERVAL`、`ACCEPTED_EVENT`、`REMOVED_FRACTION_GRID` の各測定契機と、ステップ0・終了時点が重複なく出力されること。
- `remainingEdges == 0` で正常終了し、辺が残ったまま `maxSteps` に達した場合は打ち切りとして異なる終了理由が記録されること。
- CSVのヘッダー、列順、数値型、UTF-8出力が仕様どおりであること。

### 検証テスト

小さい格子では全状態や全最短経路を列挙する参照実装と照合する。有限 `C` と `C >= N - 1` の無限予算相当も比較する。性能試験では `L`、`C`、`maxSteps` を段階的に増やし、要求処理BFS、`BigInteger` の経路数計算、測定時の全成分探索を分けて計測する。Python解析では、人工データを用いて `L` を基本変数とする指数フィットと疑似臨界点シフトの処理を検証する。

## 10. SPP用に変更した点

- 一般の有向・無向混在ネットワークではなく、無向・無重みの二次元正方格子に限定する。
- 辺を独立な確率で残すボンドパーコレーションではなく、ランダムな頂点対の最短経路を要求単位で削除する動的過程とする。
- 有向グラフ向けのin/out隣接表現ではなく、各無向辺に一意なedgeIdを割り当て、両端から共有する。
- run中に隣接構造を作り直さず、`boolean[] activeEdge` で累積的な辺削除を管理する。
- BFSを要求ごとの最短距離探索と、測定時の連結成分探索の両方に用いる。
- 原論文の「複数の最短経路から1本をランダムに選ぶ」という記述を、本研究では方向バイアスを避けるため全最短経路からの厳密な一様選択として具体化する。
- GWCCやGSCCではなく、無向グラフの通常の連結成分、最大成分、第2最大成分、有限クラスター平均を測定する。
- CSV書き込みを専用の `CsvWriter` に分離し、測定時点ごとの統一形式で出力する。
- Javaはシミュレーションと測定データ生成を担当し、Pythonは集約、可視化、有限サイズスケーリング解析を担当する。
- 初期版は開放境界だけを実装し、周期境界は将来拡張として扱う。
