# scaling-v1 研究記録

> **成果物の状態（連続監査）**：本記録はL≤64のHISTORICALな研究段階を記述する。raw・run集約・点fitは保存されたCURRENT値だが、log regressionの解析的95%区間はStudent tの正確な分位点で訂正した。現行区間は `app/out/scaling-log-ci-corrected/v1_scaling_fit_results.csv` を使用する。 最新の参照先・訂正理由は[解析監査台帳](ANALYSIS_AUDIT_CORRECTIONS.md)を参照。

## 1. 位置づけ

scaling-v1は、本番規模をさらに拡大する前に、要求単位のSPP転移と有限サイズ依存性を確認した最初の固定データセットである。本記録の数値は、生成済みの `app/out/scaling-v1` および順序感度用 `app/out/scaling-v1-order-check` のCSVから転記した。これらの生成物自体はGit管理しない。

疑似臨界事象の厳密な定義は [ANALYSIS_DEFINITIONS.md](ANALYSIS_DEFINITIONS.md) を参照する。主結果は、最短経路全体を同時削除するSPPモデルに対応したrequest-level eventである。これは原論文との比較に使うsingle-edge event-based ensembleとは異なる。

## 2. 実験条件

| 項目 | 設定 |
|---|---|
| 線形サイズ | `L = 8, 12, 16, 24, 32, 48, 64` |
| 予算 | `C = 1, 2, UNBOUNDED` |
| UNBOUNDED表現 | 各 `L` で `C = N = L^2` |
| run数 | 1条件200、合計4,200 |
| 境界 | `OPEN` |
| base seed | 42 |
| 測定 | `ACCEPTED_REQUEST` |
| 停止 | `TRANSITION_WINDOW_COMPLETE` |
| 安全上限 | `maxSteps = 2N^2` |
| edge trace | 無効 |
| bootstrap | 2,000標本、seed `20260715` |

21条件の4,200 runはすべて `TRANSITION_WINDOW_COMPLETE` で終了し、`MAX_STEPS` または全辺削除による終了はなかった。結果は3,702,767行、約411.9 MBであり、edge traceは生成していない。

診断では、全runで閾値通過とrequest eventを確認した。例外的に `L=8, UNBOUNDED, run=111` では `S` の最大が最終測定行で初めて現れた。このrunも `P=1/L=0.125` の停止条件を満たしており実行失敗ではないが、小サイズの窓端効果として記録する。

## 6. L_min別の有効指数

power law fitは線形サイズ `L` の対数に対して行った。表の `x_b`、`x_a`、`omega`、`y_b`、`y_a`、`1/nu_eff` はそれぞれ、

```text
P_before ~ L^(-x_b)
P_after  ~ L^(-x_a)
delta_P  ~ L^(-omega)
S_before ~ L^(y_b)
S_after  ~ L^(y_a)
std(p_mid) ~ L^(-1/nu_eff)
```

## 7. C=1と通常の二次元ボンドパーコレーション

比較値は `beta/nu=5/48≈0.10417`、`gamma/nu=43/24≈1.79167`、`1/nu=0.75` である。`L_min=16` では、

- `x_before=0.09309`（理論値との差 -0.01108）
- `x_after=0.07733`（差 -0.02684）
- `y_before=1.55978`（差 -0.23189）
- `y_after=1.68735`（差 -0.10432）
- `1/nu_eff=0.75130`（差 +0.00130）

であった。hyperscaling和 `2x+y` はbeforeで1.74596、afterで1.84200であり、理論値2へ完全には収束していない。

したがって、`C=1` は通常の二次元ボンドパーコレーションを概ね再現しているが、特に `S` とevent後の `P` には有限サイズ補正が残る、と解釈するのが妥当である。

> **Phase 6監査注記**：上の解釈は当時の記録である。C=1のaccepted-event削除過程が通常の一様ボンド削除と等価であることと、全指数の数値再現は別である。このL≤64のfitは最大request jump前後に条件付けた有効指数で、Sの参照値43/24はL_min=8,12,16の解析的区間外、hyperscaling和も2を再現しない。有限サイズ、開放境界、事象選択、fitの系統差は原因候補であり、補正項だけへの帰属を証明したものではない。raw・集約・fitの照合では実装上の原因は見つからなかった。

## 8. C=2の解釈

`C=2` の `P` 指数は `L_min` を上げると `C=1` および通常パーコレーションの値に近い範囲へ入る。`S` と `1/nu_eff` はまだ安定せず、`L_min` 依存性も残る。現時点では同じ普遍クラスへ向かう可能性があるが、`L <= 64` だけで同一性を断定しない。

## 9. UNBOUNDEDの解釈

UNBOUNDEDでは、`P_before` がサイズとともにほぼ一定、`P_after` も弱いサイズ依存しか示さず、平均 `delta_P` は有限 `C` より大きい。さらに `S_after` の有効指数は約2で、有限 `C` と異なる。この有限サイズ範囲では、UNBOUNDEDが有限 `C` と明確に異なる転移形状を持つことが示される。

一方、最大落下量のfitは緩やかな減衰も許している。したがって、UNBOUNDEDが真に不連続か弱い不連続かは未確定である。

> **Phase11監査注記**：上の「真の不連続／弱い不連続」はHISTORICALな表現であり、「弱い不連続」の漸近定義は指定されていない。当時のL≤64だけでは、有限の最大request jumpを残す可能性と、最大request jumpが非常にゆっくりゼロへ減衰する可能性を区別できず、連続転移を排除したものではない。有限サイズの急激さを熱力学極限の転移次数の証明として使用しない。現在のL≤384までの候補比較は後続v7記録を参照する。

## 11. 経路内辺順序の副解析

主計算とは別に、`L=16,32,64`、各50 run、`C=2` とUNBOUNDEDでedge traceを有効にし、source-to-target、逆順、決定的shuffleを比較した。6条件300 runのJava実行は約33.5秒、Python解析は約334.5秒、traceは731,263行であった。

3順序間のrangeは次のとおりである。

| L | 条件 | conventional p range | edge event p平均 range |
|---:|---|---:|---:|
| 16 | C=2 | 0.002083 | 0.000417 |
| 16 | UNBOUNDED | 0.012500 | 0.023208 |
| 32 | C=2 | 0.000000 | 0.000464 |
| 32 | UNBOUNDED | 0.006552 | 0.005151 |
| 64 | C=2 | 0.000000 | 0.000007 |
| 64 | UNBOUNDED | 0.003224 | 0.005310 |

この3順序・各50runでは、`C=2` の順序差は大サイズで小さい。UNBOUNDEDのconventional p rangeは縮小するが、edge event p平均のrangeは `L=32` の0.005151から `L=64` の0.005310へ僅かに増え、単調縮小ではない。どちらも `L=64` で差が残り、3順序の比較から任意の順序や漸近的な差の消失を保証しない。これはedge-level解析の系統要因であり、最短経路全体を同時削除するrequest-level主結果には経路内順序依存性がない。

## 12. 結論と次の課題

scaling-v1から得られた暫定的な結論は次である。

- `C=1` は通常の二次元ボンドパーコレーションを概ね再現する。
- `C=2` は同じ普遍クラスへ向かう可能性があるが、有限サイズ補正が残る。
- UNBOUNDEDは `L <= 64` で有限 `C` と明確に異なる。
- UNBOUNDEDが真の不連続か弱い不連続かは、このサイズ範囲では未確定である。
- request-level最大落下と、論文比較用のsingle-edge event-based ensembleは別の定義である。

次段階では以下を検討する。

- `L=96,128` の追加
- 補正項を含む有限サイズfitと `L_min` 感度の評価
- 開放境界と他の境界条件の比較
- UNBOUNDEDの最大要求落下量の漸近挙動
- request-levelとedge-levelの定量的な関係

これらを行うまでは、普遍クラスや転移次数について断定的な表現を避ける。
