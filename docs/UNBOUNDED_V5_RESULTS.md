# UNBOUNDED v5: L=256パイロットと漸近モデル識別力の再評価

## 1. 目的と背景

UNBOUNDED v4では、`L=8, 12, 16, 24, 32, 48, 64, 96, 128, 192`の最大request jump、transition width、request-event位置を4種類の漸近モデルで比較した。`L=192`を50 runへ増やしてもzero-logがAICc、BIC、leave-one-size-out（LOO）で相対的に良好だった一方、有限極限モデルの信頼区間は広く、ゼロ漸近も有限値漸近も排除できなかった。

v5の目的は、同じサイズの反復数をさらに増やすのではなく、新しいサイズ`L=256`を20 run追加し、v4の事前予測を外部的に確認するとともに、モデル識別力がどの程度改善するかを定量化することである。新しい20 runを確認せず50 run以上へ自動拡張することはしていない。

## 2. 実験設計

条件はUNBOUNDED、`L=256`、`C=N=65,536`、OPEN境界、`ACCEPTED_REQUEST`測定、`TRANSITION_WINDOW_COMPLETE`停止、閾値`P <= 1/L`、edge trace無効、上限`2N^2=8,589,934,592`要求である。resultsの14列と不変条件は既存実験と同じである。

| stage | run数 | 入力seed範囲 | 出力 |
|---|---:|---:|---|
| benchmark | 3 | 2,560,000–2,560,002 | `app/out/unbounded-l256/benchmark` |
| pilot | 17 | 2,560,003–2,560,019 | `app/out/unbounded-l256/pilot` |
| stop audit | 3（benchmarkと同じseed） | 2,560,000–2,560,002 | `app/out/unbounded-l256/stop-audit` |

benchmarkとpilotは別manifestで保持し、v5解析時に20 runの一つの`L=256`標本として統合した。run seedは既存L=192の段階実験と重複せず、benchmarkとpilot間にも重複がない。各runは独立shardに保存し、完全性検査後に`.complete`を作る。再実行時は完了shardを`resume-skip`し、不完全または破損したshardは受理しない。

## 3. 実行性能と容量

benchmark 3 runの実行時間は3.138、3.302、3.326秒で、平均3.255秒、中央値3.302秒だった。pilot 17 runを含む20 runの平均は3.415秒、中央値は3.427秒、最小2.947秒、最大3.879秒である。20 run本計算の実測run時間合計は68.3秒で、Gradle起動、統合、検証を含むpilot wall timeは約58.8秒、benchmark wall timeは約10秒だった。この差のため、容量計画ではrun metadataの中央値を用いる。

最大観測heap使用量は318,048,728 bytes（約303 MiB）、committed heapは512 MiBだった。benchmarkは3,100行・382,970 bytes、pilotは18,826行・2,320,929 bytesで、合計21,926行・約2.70 MB（統合resultsのみ）である。shardと統合ファイルを同時に保持するため、実際のstageディレクトリ容量は概ねその2倍になる。

中央値3.427秒/run相当の実測外挿では、合計50 runは約171秒、100 runは約343秒である。results容量はそれぞれ約6.75 MB、13.50 MB（shard複製を除く）と見積もった。L=320・20 runは約135秒、L=384・20 runは約235秒の経験的外挿であり、観測ではない。

## 4. 完全性・停止監査

benchmark 3 runとpilot 17 runはすべて`TRANSITION_WINDOW_COMPLETE`で終了した。欠損値、seed重複、run欠損、14列不変条件違反、step逆行、removed edge減少は0件だった。再実行では全20 runが`resume-skip`された。

stop auditはbenchmarkと同じ3 seedを`P <= 0.5/L`まで延長した。比較可能prefixは全行・全14列で一致し、最大request jump、request-level疑似臨界event、S peak、transition widthは3/3 seedですべて一致した。auditの最終stepは1,668,377–3,321,675で、元計算の378,727–451,917より後まで進んだが主要観測量は更新されなかった。この監査は3 seedに対する確認であり、全seedの数学的保証ではない。

## 5. L=256の観測値

20 runについてrun平均、標本標準偏差、SEM、run再標本化bootstrap 95% percentile区間を求めた。

| 観測量 | 平均または推定値 | 標準偏差 | SEM | bootstrap 95%区間 |
|---|---:|---:|---:|---:|
| 最大request jump | 0.281669 | 0.069447 | 0.015529 | [0.252301, 0.311999] |
| transition `delta_p` | 0.256329 | 0.022199 | 0.004964 | [0.246586, 0.265685] |
| `delta_t/N^2` | 0.00010925 | 0.00002257 | 0.00000505 | [0.00009996, 0.00011913] |
| request event `p_after` | 0.430537 | 0.021022 | 0.004701 | [0.421561, 0.439553] |
| run間`std(p_mid)` | 0.020852 | — | bootstrap SE 0.002655 | [0.014694, 0.025036] |
| S peak | 9,863.58 | 3,753.19 | 839.24 | [8,279.82, 11,446.80] |

20 runでは最大jumpのSEMが平均の約5.5%であり、単一サイズの平均としてまだ幅がある。したがって、L=256の点がモデル間の小さな差を単独で決定するとは解釈しない。

## 6. v4事前予測との比較

v4がL=256について生成した予測と、今回初めて得た観測平均を比較した。これは同じデータでfitの良さを測る事後比較ではなく、L=256を含まないfitの外挿確認である。

| model | v4予測 | 予測誤差（予測−観測） | v4予測区間 | 観測平均が区間内 |
|---|---:|---:|---:|---|
| zero-power | 0.276114 | -0.005555 | [0.267798, 0.286299] | yes |
| finite-power | 0.285641 | +0.003972 | [0.270552, 0.298918] | yes |
| zero-log | 0.282408 | +0.000739 | [0.274828, 0.290002] | yes |
| finite-log | 0.285153 | +0.003484 | [0.276018, 0.298135] | yes |

全モデルの事前予測区間に観測平均が入った。点予測誤差はzero-logが最小だったが、この1点だけでzero-logを確定する根拠にはならない。観測bootstrap区間は4予測の全範囲より広い。

## 7. 漸近モデル比較

比較したモデルはv4と同一である。

```text
zero-power:   Y(L) = a L^(-x)
finite-power: Y(L) = Y_inf + a L^(-x)
zero-log:     Y(L) = a / (log L)^q
finite-log:   Y(L) = Y_inf + a / (log L)^q
```

`a>0`、`Y_inf in [0,1]`、powerの`x in [0.001,5]`、logの`q in [0.001,10]`とし、複数初期値、共分散、境界到達、最大パラメータ相関、AIC/AICc/BIC、LOO、run-stratified bootstrap 500標本、`L_min`依存性を記録した。

最大request jumpの結果は次の通りである。

| model | `Y_inf` | xまたはq | AICc | BIC | LOO MAE | LOO RMSE |
|---|---:|---:|---:|---:|---:|---:|
| zero-power | 0固定 | 0.07051 | -103.85 | -104.56 | 0.00741 | 0.00961 |
| finite-power | 0.25968 | 0.41702 | -103.78 | -106.01 | 0.00733 | 0.00997 |
| zero-log | 0固定 | 0.25251 | **-108.21** | **-108.91** | **0.00586** | **0.00770** |
| finite-log | 0.16592 | 0.52735 | -104.55 | -106.78 | 0.00623 | 0.00815 |

zero-logはv5でもAICc、BIC、LOO MAE/RMSEで最良だった。v4からv5へのLOO MAEはzero-logで0.00655から0.00586へ、LOO RMSEは0.00831から0.00770へ改善した。ただしfinite-logとの差はAICcで3.66、BICで2.13、LOO MAEで0.00037にすぎず、漸近極限の識別として決定的ではない。

有限powerの`Y_inf` bootstrap区間は[0.000003, 0.295826]、有限logは[0.0000003, 0.290310]である。下端は0境界近傍で、`Y_inf`と減衰指数の相関はfinite-power 0.9769、finite-log 0.9973だった。全500 bootstrap fitは数値的には収束したが、この高相関とL_min依存性は有限極限推定の構造的不安定性を示す。区間下端が数値的に正であることを、ゼロ極限排除とは解釈しない。

transition `delta_p`、`delta_t/N^2`、event位置分散も同じ4モデルで比較した。観測点数に対して3パラメータモデルの自由度は小さく、有限モデルでは境界解や強相関が現れる。都合のよいfitだけを採用せず、全表を`app/out/unbounded-v5/`へ保存した。

## 8. L=256追加で変わったこと

- v4の4モデルはすべてL=256観測を予測区間内に含み、明確に外れたモデルはなかった。
- zero-logはAICc/BIC/LOOで首位を維持し、LOO誤差はわずかに改善した。
- 最大jumpの4モデル間のL=256再fit値rangeは約0.0061だが、観測SEMは0.0155でより大きい。
- 有限モデルの`Y_inf`区間幅はほとんど縮まず、パラメータ相関は依然0.98–1.00近傍である。
- L=256という新しいleverageは有用だったが、zero/finite漸近の識別力を決定的にはしなかった。

したがって暫定結論は「zero-logが相対的に優勢だが、有限値漸近を排除できず、現在も判定不能」である。ゼロ漸近が明確に支持された、または有限値漸近が明確に支持されたとは言わない。

## 9. 外挿と次の実験候補

L=256を最大観測サイズとして、最大request jumpの4モデルによる点外挿rangeは以下である。

| target L | モデル間点予測range | 最大観測Lからの倍率 |
|---:|---:|---:|
| 320 | 0.27334–0.28165 | 1.25 |
| 384 | 0.26985–0.28005 | 1.50 |
| 512 | 0.26443–0.27774 | 2.00 |
| 768 | 0.25698–0.27493 | 3.00 |

これらは観測値ではなく、モデル仮定に依存する外挿である。全targetでbootstrap予測区間は重なっており、遠い外挿ほどモデル間rangeが増える。

候補A（L=256を50 run）ではjump SEMを単純な`1/sqrt(n)`で約0.00982、候補B（100 run）では約0.00694へ下げられるが、同一サイズの統計誤差だけを減らし、漸近曲率の識別には直接新しい情報を加えない。候補C（L=320または384を20 run）は実行時間・メモリの外挿リスクを伴う一方、モデル間差を直接制約する新しいサイズ情報を加える。候補Dは現時点の不確実性を明記して停止する。

費用対効果の観点では、次に計算するならL=256の反復数追加より、まずL=320の少数run benchmarkと20 run pilotを優先するのが妥当である。benchmarkで性能と停止完全性を確認してから拡張し、L=384以上はその結果を見て判断する。これは推奨であり、本v5作業では追加計算していない。

## 10. 再現手順と成果物

```powershell
.\gradlew.bat run --args="--unbounded-l256-benchmark"
.\gradlew.bat run --args="--unbounded-l256-pilot"
.\gradlew.bat run --args="--unbounded-l256-stop-audit"
python -m analysis.unbounded_v5 --bootstrap-samples 500 --output app/out/unbounded-v5
```

解析は観測量、model fit、LOO、bootstrap、`L_min`、外挿、v4/v5比較、事前予測確認、データ品質、seed監査、停止監査、費用対効果のCSVと15図を生成する。図には軸名、モデル、サイズ範囲、観測と外挿の区別を付けた。CSV/PNGと生データはすべて`app/out/`以下でGit管理対象外である。

## 11. 卒論本文に使える要約

UNBOUNDED条件の漸近挙動を再評価するため、既存の最大サイズL=192に加え、L=256で20独立runを実行した。L=256の最大request jumpは0.2817±0.0155（SEM）であり、L=256を含まないv4の4モデル予測区間すべてと整合した。L=256を含む再fitではzero-logモデルがAICc、BIC、LOOで最良だったが、有限極限モデルの極限値と減衰指数には0.98以上の強い相関が残り、bootstrap区間はゼロ近傍から約0.29まで広がった。したがって、観測サイズL≤256ではzero漸近が相対的に優勢であるものの、有限値漸近を排除できず、転移次数は未確定である。次の情報価値は同一サイズのrun追加よりも、段階的なL=320追加実験の方が高いと判断した。

## 12. 限界

- L=256は20 runであり、小さいrun間SEMではない。
- サイズ平均への非線形fitであり、サイズ間の系統誤差や停止規則依存を完全にはモデル化していない。
- 有限モデルの境界制約と高相関により、通常の共分散近似を楽観視できない。
- 対数モデルは遅い収束の経験的候補であり、厳密な理論導出ではない。
- stop auditは3 seedのみである。
- L=320以上の時間、容量、観測量は外挿であり、実測ではない。
